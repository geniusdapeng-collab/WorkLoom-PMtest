# eval 集锻造（eval 即 PRD）

## 一、何时调用
- 需求定义阶段：与 PRD 同步产出 eval 骨架，作为审批卡附件一并提交；
- eval 集增补阶段：badcase 回流人审批准后，批量转化为新案例。

## 二、输入契约
- PRD 五章骨架或需求条目（含成功标准草案）；行业包种子/运行时事件流；
- 关联的模型与 prompt 版本（用于首跑基线）。

## 三、执行步骤
1. 从 PRD 的「目标/边界/验收」提取可检验行为点，覆盖核心路径/边界/对抗三类；
2. 按需求与风险覆盖生成最小完整评测集；用户指定数量时遵守，未指定时不为凑数量扩写。每个案例含输入、唯一期望输出（golden answer）与评分规则，必要的正常/边界/错误/权限/回归维度不得省略；
3. **评分双轨制**：能确定性断言的（格式/字段/关键词/规则）生成断言脚本，绝不用 judge；必须主观判断的才生成 judge rubric，且 rubric 随案例一并呈现；
4. 首跑基线：在当前模型+prompt 上执行一遍，产出基线通过率与成本；
5. eval 集版本化入库，变更走 R-PM10 人审。

6. 每例有稳定编号、来源需求、前置条件、输入、步骤、预期、判定器和实际结果栏；实际未运行必须写未运行。覆盖正常、边界（空/最大/重复/特殊字符/并发适用项）、错误、权限、历史回归，标明不适用理由。
7. 确定性判定器独立于被测实现，不能用被测输出反推期望或只断言文件存在。用错误实现/坏例验证断言能失败；主观判定提供评分锚点和分歧处理，未校准 judge 不独自决定放行。用例数量与已执行成绩分开，不能靠增加文档行数制造覆盖完整的印象。
8. 输出评测集时就冻结契约，不能留“截断或拒绝均可”“标签甲或乙，以 golden 为准”之类待选项。每例列具体固定输入（长输入可用精确生成式）、唯一 expected_route、精确 golden_label 或明确 null、固定输出/错误码及可判负断言。业务未给的配置可自行选择合理假设并写明，再按该假设只允许一种行为；鉴权缺失与已认证无权限不得混成同一个案例和错误码。
9. 把模式路由召回、内容分类准确率、端到端交付达成、拒绝正确率分开：模式路由只判断是否进入预期执行模式/处理器，不用分类标签替代；分类准确率只对预期允许分类的样本计分；预期拒绝/校验失败的空值、超长或无权限样本按冻结策略计入拒绝分母，不能同时称“应受理分类”。端到端交付分母必须为所有预设应交付样本，不能先排除路由失败；可另报条件交付率但必须命名条件。
10. 每个指标明确列分母的稳定 case/step ID、单位（案例还是请求）及公式；重复/空白变体拆出步骤 ID，避免一例多请求被计两次或遗漏。执行前只报告设计分母，实测分母为 0 时分数写 not-run/未定义，不能记 0% 或 100%。表格、正文与公式的 ID 集合须一致。
11. 为避免多套编号漂移，先写唯一案例总表，每行只对应一次被测请求和一个主 ID；去重场景的已存在条目写前置夹具，两次实际请求则拆两行。所有变体、保留集和历史回归也必须进入这张总表，不在后文追加未编号案例，不再另设分类/拒绝别名编号。逐例详情复用主 ID，按总表筛选生成路由集合、golden_label 非空且应分类的集合、应拒绝集合和应交付集合；计数用各集合的明确 ID 数量，交集/补集逐项核对。若新增一行必须同步所有集合和总数。优先用满足所需风险覆盖的最小完整集合，避免为凑样本数扩写后失去一致性。
12. 总表冻结优先级、覆盖维度、边界单位和唯一预期，门禁、维度统计及详情只引用主 ID，不在多处手填另一套集合。边界输入使用可证明长度的精确生成式，或真实计算并注明码点/UTF-16/字节单位；普通输入不需要附精确长度，未实算就省略或写未计算，禁止凭目测编数。不能用“前几项均接受”概括含不合法输入的列表。覆盖维度可重叠，但须说明统计单位；维度计数不能相加当总样本数，除非集合互斥。
13. 每个案例独立列明初始实例/已有条目/计数器/权限夹具与完整操作顺序，不隐式继承上一案例的状态；只引用已明确构造的变量、ID和数组位置。逐步推演操作后的状态、数组长度与计数器，再核对预期；访问索引前核对该项确实存在，编号递增预期要包含所有导致编号增长的前置操作。
14. 坏实现与用例必须有真实区分力：给出错误规则、选定输入、正确预期与错误实现会产生的不同结果；若此输入让好坏实现输出相同，不能声称该例覆盖此坏实现，须换成能区分的输入。只列一个错误名称或案例 ID 不等于已证明判负；没实际运行仍标设计推演/未运行。
15. 训练/测试泄漏能证明独立性失效，不能单凭重叠证明成绩必然高估、低估或偏差大小；没有有效对照时，方向与幅度均未知，摘要和正文须一致。保留原描述性分数并标污染；再评测优先使用未暴露的新保留集。只从训练文件删掉样本不能消除已训练模型的记忆；采用重训方案须从未接触污染样本的基线重训并留下实际回执，不能把文件修改当去污染证明。

## 四、边界与围栏
- 权限面：eval 集写库（R-PM10 人审生效）；跑分执行走谷时窗口控成本。
- 案例中含用户数据必须脱敏；绝不编造跑分结果，无回执标「未核实」。

## 五、与其他技能的协作
- 上游：prd-forge（PRD 骨架）；
- 下游：prompt-regression / model-scout（以本 eval 集为回归与试跑基准）、badcase-harvest（失败案例回流入口）；
- 审批：eval 骨架随 PRD 审批卡提交（产品总监组织，人批准后同时生效）。
